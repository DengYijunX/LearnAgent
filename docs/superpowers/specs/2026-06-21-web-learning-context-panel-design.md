# LearnAgent Web 学习上下文面板设计

## 背景

LearnAgent CLI 已提供主题、计划模式、学习进度、会话、工具、长期记忆和后台进程等能力。当前 Web 会话页只展示聊天主流程，空间简洁但缺少学习任务的全局上下文。

本设计将 CLI 中适合图形界面的真实能力转化为 Web 组件，并参考 `design` 文件夹中会话页的信息层级，为现有 Apple 风格会话页增加自适应学习上下文面板。

设计不直接复制 CLI 命令输出，也不使用占位统计或虚构学习数据。

## 目标

- 在不破坏聊天阅读体验的前提下展示当前学习任务的真实状态。
- 将 CLI 能力转换为适合 Web 的卡片、列表、状态和操作。
- 为学习计划、长期记忆和后台进程建立清晰的数据接口。
- 修复 Web 已暴露但服务端尚未实现的停止行为。
- 保持现有冷白、浅蓝、克制毛玻璃的视觉语言。

## 非目标

- 不在本轮创建总览、知识库、GitHub 分析或进度复盘独立页面。
- 不将 `/help`、`/sessions`、`/tools` 等 CLI 文本原样展示在 Web 中。
- 不展示伪造的学习时长、完成率、难度评分或未来计划。
- 不引入移动端专用信息架构。
- 不展示 API Key、路径之外的敏感配置值。

## 布局

页面采用自适应三栏结构：

- 左栏固定约 268px，继续承载品牌、新建会话和历史会话。
- 中栏承载当前聊天、工具调用消息和输入框。
- 右栏宽约 300px，承载学习上下文。

### 自适应规则

- 视口宽度不低于 1440px 时，右栏默认展开。
- 较窄桌面视口下，右栏默认收起为抽屉。
- 顶栏提供“学习上下文”按钮，用于展开或收起右栏。
- 展开后允许固定；固定与收起选择保存到 `localStorage`。
- 收起状态不保留悬浮胶囊或边缘图标，避免干扰聊天。
- 右栏展开时，中栏仍保持可读宽度；消息正文不被拉伸到全宽。

## 视觉语言

- 右栏延续冷白半透明玻璃，以细边框、轻阴影和背景模糊区分层级。
- 卡片不使用厚重阴影和高饱和渐变。
- 标题、正文和辅助文字遵循现有 `--ink` 颜色层级。
- 主交互使用 Apple Blue；成功、警告和失败色只表示真实状态。
- 图标统一使用 Lucide Vue，不使用 emoji。
- 展开、收起和状态变化使用 150–240ms 过渡，并尊重 `prefers-reduced-motion`。

## 面板结构

右栏从上到下按照任务相关性排列。

### 1. 面板头部

- 标题为“学习上下文”。
- 提供刷新、固定和关闭操作。
- 刷新只重新获取面板所需数据，不重载聊天页。
- 显示最后刷新时间或加载状态。

### 2. 当前主题

- 显示当前主题、当前意图和探索/完整模式。
- 无主题时明确显示“尚未识别主题”。
- 支持切换模式。
- 主题编辑通过明确操作进入，不使用不可发现的双击交互。
- 主题修改写入当前会话并通过 WebSocket 同步。

### 3. 学习计划

- 展示当前会话的 Todo 列表。
- 每项包含内容和 `pending`、`in_progress`、`completed` 状态。
- 进行中任务置于列表顶部并有克制的蓝色状态提示。
- 已完成任务可折叠，避免面板过长。
- 计划为空时显示真实空状态：“Agent 生成学习计划后会显示在这里”。
- 第一阶段只展示 Agent 维护的任务，不提供用户直接编辑，避免双向状态冲突。

### 4. 工具与后台进程

- 当前执行中的工具优先显示名称、状态和耗时。
- 无正在执行工具时，显示可用工具数量和最近一次工具摘要。
- 后台进程显示命令、PID、端口和运行时长。
- 停止进程必须确认，确认内容包含 PID 和命令摘要。
- 进程模块为空时保持紧凑，不渲染大面积空卡片。

### 5. 长期记忆

- 展示最近的学习记忆条目，默认最多三条。
- 每条显示描述、主题和正文摘要。
- 点击条目展开详情，不在第一阶段提供编辑或删除。
- 无记忆时说明产生条件，不使用占位内容。

### 6. 系统状态与快捷操作

- 展示模型模式、API Key 是否已配置和 WebSocket 连接状态。
- 不展示 API Key 内容、完整本地路径或其他敏感配置。
- 快捷操作包括：切换探索/完整模式、刷新上下文、清空当前消息视图。
- 清空消息视图需要确认，并明确不会删除长期记忆。
- CLI 帮助文本不进入右栏；按钮直接表达动作。

## CLI 能力映射

| CLI 能力 | Web 表达 | 数据来源 |
|---|---|---|
| `/plan` | 模式切换按钮 | Session + WebSocket |
| `/topic` | 当前主题卡与编辑操作 | Session + WebSocket |
| `/progress` | 学习计划与记忆摘要 | Todo + Memory API |
| `/sessions` | 左侧会话列表 | Sessions API |
| `/tools` | 工具状态与可用数量 | Tools API + WebSocket |
| `/memory` | 最近学习记忆 | Memories API |
| `/processes` | 后台进程列表 | Processes API |
| `/kill` | 带确认的停止按钮 | Process stop API |
| `/status`、`/model` | 系统状态卡 | Config API |
| `/clear` | 带确认的清空视图操作 | 前端会话状态 |
| `/help` | 不迁移 | Web 使用可发现控件 |

## 数据模型

### 学习 Todo

Todo 从当前仅存在于工具返回值的临时数据，升级为会话级状态：

```text
LearningTodo
- content: string
- active_form: string | null
- status: pending | in_progress | completed
```

Todo 随会话持久化。`learning_todo_write` 更新 Todo 后，服务端通过 WebSocket 发送完整快照，前端替换当前列表，避免增量事件乱序。

### 长期记忆

Memory API 返回只读条目：

```text
LearningMemory
- name: string
- description: string
- type: string
- body: string
```

第一阶段只读取 `learning` 类型，并在服务端限制返回数量与正文长度。

### 后台进程

复用现有进程对象字段：PID、命令、端口、运行时长和状态。停止操作继续校验进程属于当前会话。

## 接口增量

### REST

- `GET /api/memories?type=learning&limit=10`
  - 返回最近学习记忆。
- `GET /api/sessions/{session_id}/todos`
  - 返回当前会话 Todo 快照。
- `GET /api/processes?session_id={session_id}`
  - 复用现有接口并在前端定时刷新。
- `POST /api/processes/{pid}/stop?session_id={session_id}`
  - 复用现有接口，停止属于当前会话的进程。
- `GET /api/config`
  - 复用现有安全配置摘要。

### WebSocket 服务端事件

- `todo_update`
  - 携带当前会话完整 Todo 快照。
- `process_output`
  - 保留现有事件；右栏只展示进程摘要，详细输出仍留在消息上下文或后续专用视图。
- `session_ready`
  - 继续同步主题与权限模式。

### WebSocket 客户端事件

- `cancel`
  - 服务端取消当前 `agent_task`，发送明确的取消完成事件或错误事件。
- `set_mode`
  - 继续负责模式切换。
- `set_topic`
  - 新增主题更新事件，服务端校验并持久化。

现有 `command` 客户端消息不再使用。Web 操作通过明确 API 或明确事件完成，避免维护第二套 CLI 命令解析入口。

## 前端组件边界

- `LearningContextPanel.vue`
  - 负责右栏外壳、展开状态、刷新与子模块布局。
- `CurrentTopicCard.vue`
  - 负责主题、意图和模式。
- `LearningPlanCard.vue`
  - 负责 Todo 状态与折叠。
- `RuntimeStatusCard.vue`
  - 负责当前工具和后台进程。
- `MemorySummaryCard.vue`
  - 负责长期记忆摘要。
- `SystemStatusCard.vue`
  - 负责模型、配置和连接状态。
- `ToastViewport.vue`
  - 负责全局轻量错误与成功提示。
- `ConfirmDialog.vue`
  - 复用在停止进程和清空视图等确认操作。

面板通过 Pinia store 获取共享状态，不直接管理 WebSocket 生命周期。API 获取逻辑放入单独 client/store，避免组件承担协议解析。

## 状态管理

- `session` store：继续管理当前会话、主题、模式与会话列表。
- `chat` store：继续管理消息、当前工具调用和处理状态。
- 新增 `context` store：管理 Todo、记忆、进程、系统摘要、加载状态和分区错误。
- 面板展开/固定偏好保存在独立 composable 与 `localStorage`，不进入服务端。
- 切换会话时清理旧上下文，再并行加载新会话 Todo、进程和共享记忆。

## 数据流

1. 用户选择会话。
2. WebSocket 返回 `session_ready`，更新主题与模式。
3. context store 并行请求 Todo、进程、记忆和配置摘要。
4. Agent 执行工具时，现有事件更新工具状态。
5. `learning_todo_write` 成功后，服务端发送 `todo_update` 完整快照。
6. 进程模块按低频轮询刷新；面板收起时降低刷新频率。
7. 切换会话或断开连接时停止旧会话轮询。

## 错误与空状态

- 每个模块独立处理加载、空、成功和失败状态。
- 单一模块失败不阻塞整个面板。
- API 错误显示轻量 Toast，并在对应卡片提供重试。
- WebSocket 断开时保留最后一次数据，但标记为可能过期。
- 停止 Agent 或进程失败时显示明确原因，不提前移除项目。
- 记忆或 Todo 接口返回空数组时显示真实产生条件。

## 可访问性

- 面板切换按钮使用动态 `aria-expanded` 与 `aria-controls`。
- 抽屉模式正确管理焦点；关闭后焦点返回触发按钮。
- 固定模式不使用模态语义。
- 状态不只依赖颜色，始终包含图标和文字。
- 确认弹窗支持 Tab 焦点锁定、Esc 取消与初始安全焦点。
- 所有动画尊重减少动态效果设置。

## 验证标准

### 自动验证

- REST 接口覆盖成功、空数据、非法 session、limit 边界和敏感信息过滤。
- WebSocket 覆盖 Todo 更新、取消任务、主题更新和会话切换。
- 前端 store 覆盖并行加载、分区错误、会话切换和过期请求处理。
- 组件覆盖展开/收起、默认断点、偏好持久化、空状态与确认操作。
- `npm run check`、`npm run build` 和完整 Python 测试通过。

### 浏览器验证

- 1280px 默认收起，聊天区无水平溢出。
- 1440px 及更宽默认展开。
- 用户手动选择覆盖默认断点并在刷新后保留。
- 右栏打开、关闭和固定不改变消息滚动位置。
- 切换会话不会短暂显示上一会话 Todo 或进程。
- Todo、工具、进程和记忆的加载、空、错误和真实数据状态均正确。
- 停止 Agent、停止进程和清空消息具有明确确认与结果反馈。
- 控制台无未处理错误，键盘焦点路径完整。

## 实施顺序

1. 补齐服务端 Todo 持久化、Memory API、取消任务和主题更新协议。
2. 建立前端 context store、API 类型和 Toast/确认基础组件。
3. 实现右栏外壳、自适应断点与偏好持久化。
4. 依次接入主题、Todo、工具/进程、记忆和系统状态卡。
5. 完成浏览器验证和视觉细节调整。
